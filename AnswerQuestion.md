# Контрольні питання
-----
## 1\. Що таке структурне програмування
**Структурне програмування** — це методологія розробки програм, у якій програма будується з невеликої кількості стандартних керуючих конструкцій (послідовність, розгалуження, цикл) та підпрограм, а безумовні переходи (goto) не використовуються або зведені до мінімуму.

Мета — зробити код **зрозумілим, передбачуваним, легким для тестування та супроводу**.

-----
## 2\. Основні конструкції структурного програмування
1. **Слідування (послідовність)** — інструкції виконуються одна за одною.
1. **Розгалуження (вибір)** — виконання залежить від умови (if, if-else, switch).
1. **Цикл (повторення)** — багаторазове виконання блоку (while, do-while, for).

Кожна з конструкцій має **один вхід і один вихід**, тому їх можна вкладати одну в одну. За теоремою Бьома–Якопіні цих трьох конструкцій достатньо для запису будь-якого алгоритму.

-----
## 3\. Основні принципи структурного програмування
- Використання лише базових керуючих конструкцій (послідовність, розгалуження, цикл).
- **Відмова від goto** (або його мінімальне використання).
- **Модульність** — розбиття програми на підпрограми (методи), кожна з яких виконує одну чітку задачу.
- **Проектування зверху вниз** (покрокова деталізація) — від загальної задачі до окремих деталей.
- Кожен блок має **один вхід і один вихід**.
- Чітке оформлення коду: відступи, зрозумілі імена, коментарі.
-----
## 4\. Чому не радять використовувати goto, а в Java його немає
goto дозволяє стрибнути в довільне місце програми. Через це:

- порушується лінійна структура коду, його важко **читати та відстежувати**;
- складно **налагоджувати і тестувати** — незрозуміло, яким шляхом виконання потрапило в дану точку;
- ускладнюється формальна перевірка коректності та оптимізація;
- з'являється ризик пропустити ініціалізацію змінних, вийти з блоку «не по-людськи»;
- код перетворюється на **спагеті-код**.

У Java goto **зарезервоване** як слово, але **не використовується** (так само як const). Розробники мови свідомо відмовилися від нього: усі практичні потреби покриваються конструкціями break/continue (у тому числі з мітками), return, а також обробкою винятків (try-catch-finally).

-----
## 5\. Що таке спагеті-код
**Спагеті-код** — це погано структурований, заплутаний код із великою кількістю безладних переходів (goto), глибокої вкладеності та взаємозалежностей, у якому важко простежити хід виконання, як клубок спагеті. Його складно читати, змінювати та виправляти в ньому помилки.

-----
## 6\. Проектування зверху вниз
**Проектування зверху вниз (top-down design)** — підхід, за якого спочатку формулюється загальна задача, а потім вона послідовно розбивається на підзадачі, кожна з яких деталізується далі, доки не отримаємо прості, легко реалізовувані частини (методи).

**Переваги:**

- програма має чітку ієрархічну структуру;
- задачу простіше зрозуміти й спланувати;
- можливість **розподілити роботу** між кількома розробниками;
- кожну частину можна **тестувати окремо**;
- менше помилок, простіший супровід і повторне використання модулів.
-----
## 7\. Область видимості ідентифікатора
**Область видимості (scope)** — це частина програми, у якій ідентифікатор (змінна, метод, клас) **доступний** і може бути використаний за своїм іменем.

Наприклад, локальна змінна видима від місця оголошення до кінця блоку, у якому вона оголошена.

-----
## 8\. Що таке блок і як він впливає на область видимості
**Блок** — це група інструкцій, взята у фігурні дужки { ... }. Синтаксично блок вважається однією інструкцією.

Змінна, оголошена всередині блоку, **існує лише в межах цього блоку** і зникає після його завершення. Вкладені блоки бачать змінні зовнішніх блоків, але зовнішні не бачать змінних внутрішніх.

У Java **не можна** оголошувати у внутрішньому блоці локальну змінну з тим самим іменем, що й у зовнішньому блоці того ж методу.

int x = 10;\
{\
`    `int y = 5;\
`    `System.out.println(x + y); // OK: x видно зсередини блоку\
}\
System.out.println(y);          // помилка компіляції: y поза областю видимості

## 9\. Коли використовувати розгалуження
**if** — коли потрібно виконати дію лише за виконання умови, інакше нічого не робити.

if (balance < 0) {\
`    `System.out.println("Увага: борг!");\
}

**if-else** — коли є рівно два взаємовиключні варіанти.

if (age >= 18) {\
`    `System.out.println("Дорослий");\
} else {\
`    `System.out.println("Неповнолітній");\
}

**Ланцюг if - else if - else** — коли варіантів багато і умови є **діапазонами** або складними логічними виразами.

if (score >= 90) grade = 'A';\
else if (score >= 75) grade = 'B';\
else if (score >= 60) grade = 'C';\
else grade = 'F';

**switch** — коли вибір робиться за **конкретним дискретним значенням** однієї змінної (int, char, String, enum) і варіантів багато.

switch (dayOfWeek) {\
`    `case 6:\
`    `case 7:  System.out.println("Вихідний"); break;\
`    `default: System.out.println("Робочий день");\
}

**Тернарна операція ?:** — коли потрібно **вибрати значення** з двох за простою умовою, зазвичай у присвоєнні або виразі.

int max = (a > b) ? a : b;

## 10\. Коли використовувати цикли
**while** — коли кількість ітерацій наперед невідома, а умову потрібно перевіряти **до** виконання тіла (тіло може не виконатися жодного разу).

while (!file.endReached()) {\
`    `process(file.next());\
}

**do-while** — коли тіло має виконатися **принаймні один раз**, а умова перевіряється після (наприклад, меню або введення з перевіркою коректності).

do {\
`    `System.out.print("Введіть число > 0: ");\
`    `n = scanner.nextInt();\
} while (n <= 0);

**for** — коли кількість ітерацій **відома заздалегідь** або є явний лічильник.

for (int i = 0; i < 10; i++) {\
`    `System.out.println(i);\
}

-----
## 11\. Чим break відрізняється від continue
- **break** — **повністю завершує** найближчий цикл (або switch) і передає керування на інструкцію після нього.
- **continue** — **припиняє поточну ітерацію** та переходить до наступної (у for — до виразу оновлення, у while/do-while — до перевірки умови).

for (int i = 1; i <= 5; i++) {\
`    `if (i == 3) continue; // пропускає 3\
`    `if (i == 5) break;    // зупиняє цикл на 5\
`    `System.out.print(i + " ");\
}\
// Вивід: 1 2 4

-----
## 12\. Навіщо в Java мітки, якщо немає goto
**Мітки** використовуються разом із break і continue, щоб керувати **зовнішнім** (не лише найближчим) циклом. Це дає змогу, наприклад, вийти одразу з кількох вкладених циклів без додаткових прапорців. На відміну від goto, мітка дозволяє лише вийти із вкладеної конструкції або перейти до наступної ітерації, але **не стрибнути в довільне місце**, тому структурованість коду зберігається.

outer:\
for (int i = 0; i < 5; i++) {\
`    `for (int j = 0; j < 5; j++) {\
`        `if (i \* j == 6) {\
`            `System.out.println("Знайдено: " + i + ", " + j);\
`            `break outer; // вихід з обох циклів\
`        `}\
`        `if (j > i) continue outer; // перехід до наступної ітерації зовнішнього циклу\
`    `}\
}

## 13\. Аналіз фрагмента з оператором присвоєння в if
boolean a = false;\
boolean b = false;\
if (a = false) {\
`    `System.out.println("a is false");\
}\
if (b = true) {\
`    `System.out.println("b is true");\
}\
if (a = b) {\
`    `System.out.println("a = b");\
}

**Результат виконання:**

b is true\
a = b

**Пояснення:**

У дужках if використовується оператор **присвоєння =**, а не порівняння ==. Вираз присвоєння повертає **присвоєне значення**, і саме воно є умовою.

1. if (a = false) — a стає false, умова false → блок **не виконується**.
1. if (b = true) — b стає true, умова true → виводиться b is true.
1. if (a = b) — a отримує значення b (тобто true), умова true → виводиться a = b.

Для boolean такий код компілюється, тому помилку легко не помітити. Для порівняння слід писати a == false (або просто !a).

## 14\. Аналіз фрагмента з switch
int a = 1;\
a++;\
++a;\
switch(a) {\
`    `case 1: System.out.println("1");\
`    `case 2: System.out.println("2");\
`    `case 3: System.out.println("3");\
`    `case 4: System.out.println("4");\
}

**Результат виконання:**

3\
4

**Пояснення:**

1. a = 1, після a++ → 2, після ++a → 3.
1. switch переходить на case 3 і виводить 3.
1. Оскільки в жодній гілці немає break, відбувається **«провалювання» (fall-through)**: виконується наступна гілка case 4 і виводиться 4.
1. Гілки case 1 та case 2 пропускаються, бо управління передається одразу на відповідну мітку.

Щоб виконувалась лише одна гілка, потрібно додати break; після кожного case.

## 15\. Аналіз фрагмента з обчисленням суми
double sum = 0;\
// Let's find: 1 + 1/2 + 1/3 + 1/4 + 1/5 + ...\
for(int i=1; i<10; i++) {\
`    `sum = sum + 1/i;\
}\
System.out.println(sum > 1);

**Результат виконання:**

false

**Пояснення:**

i має тип int, тому вираз 1/i — це **цілочисельне ділення**, у якому дробова частина відкидається:

- i = 1: 1/1 = 1
- i = 2..9: 1/i = 0

Отже, sum = 1 + 0 + 0 + ... = 1.0, а умова sum > 1 дає false (1.0 не більше за 1).

**Виправлення:** зробити хоча б один операнд дробовим:

sum = sum + 1.0 / i;

Тоді сума становитиме приблизно 2.829, і sum > 1 дасть true.
